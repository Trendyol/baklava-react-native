# Stepper

A stepper guides users through a multi-step process by showing the current step, step title, and progress across discrete segments.

The stepper is used for flows such as onboarding, checkout, or form wizards. It visually shows which steps are completed, which step is active, and which steps remain. Navigation between steps is handled externally through Back and Next buttons — the step segments themselves are not interactive.

## Usage

```jsx
<Stepper
  currentStep={2}
  totalSteps={4}
  stepTitle="Contact Information"
  nextStepTitle="Payment Information"
/>
```

The component is controlled. The `currentStep` value comes from the parent, so the header text and segment states update whenever the parent passes a new value.

```jsx
const [currentStep, setCurrentStep] = useState(1);

<Stepper
  currentStep={currentStep}
  totalSteps={4}
  stepTitle={stepTitles[currentStep - 1]}
  nextStepTitle={stepTitles[currentStep]}
/>
```

<br />

## Props

#### currentStep

Type: `number`

The current step number (1-indexed). Values outside the `1..totalSteps` range are clamped.

#### totalSteps

Type: `number`

The total number of steps in the process. Determines how many segment bars are rendered.

#### stepTitle

Type: `string`

The title of the current step, displayed after the step counter in the header.

#### stepLabelPrefix

Type: `string`

Optional. Prefix for the step counter label. Default value is `Step`. Use this prop for i18n support.

#### nextStepTitle

Type: `string`

Optional. Title of the next step, displayed as a hint below the progress bars.

#### nextStepLabelPrefix

Type: `string`

Optional. Prefix for the next step hint. Default value is `Next`. Use this prop for i18n support.

#### showNextStep

Type: `boolean`

Shows the next step hint below the progress bars. Only displayed when `nextStepTitle` is provided and the current step is not the last step. Default value is `true`.

#### stepStates

Type: `('default' | 'active' | 'success' | 'error')[]`

Optional. Override array to set the state of each segment bar individually. When not provided, states are derived automatically from `currentStep`:

- Steps before the current step → `success`
- Current step → `active`
- Steps after the current step → `default`

Use `stepStates` to mark a previous step as `error`.

```jsx
<Stepper
  currentStep={3}
  totalSteps={4}
  stepTitle="Payment Information"
  nextStepTitle="Confirmation"
  stepStates={['success', 'error', 'active', 'default']}
/>
```

#### barHeight

Type: `number`

Optional. Height of each segment bar in pixels. Default value is `6`.

#### testID

Type: `string`

Test identifier prefix. Default value is `stepper`.

<br />

## States

Each segment bar can be in one of four states:

| State | Color | Description |
|-------|-------|-------------|
| `default` | Light gray | Step not yet reached |
| `active` | Orange | Current step |
| `success` | Green | Step completed successfully |
| `error` | Red | Step completed with an error |

When `stepStates` is not provided, states are derived from `currentStep`:

```jsx
<Stepper
  currentStep={2}
  totalSteps={4}
  stepTitle="Contact Information"
  nextStepTitle="Payment Information"
/>
```

<br />

## Interaction

The step segments are **not clickable**. Users navigate between steps using external Back and Next buttons provided by the parent screen.
